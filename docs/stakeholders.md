# Stakeholders

| Stakeholder | Need | Responsibility | System interaction |
| --- | --- | --- | --- |
| Employee | A clear way to submit and track a request | Provide complete request details and cancel only when still eligible | Create requests; view own status, SLA, approvals, fulfillment, and audit history |
| Manager | A focused view of direct-report requests needing a decision | Assess business need and approve or reject with a reason when rejecting | Review assigned queue and record one decision |
| Finance | Consistent review of higher-cost requests | Evaluate requests routed at or above the threshold | Review the shared Finance queue and record one decision |
| IT / Procurement | A prioritized fulfillment queue with ownership | Take an approved request, perform the work, and record completion | Start processing and complete only requests they own |
| Administrator / Management | Operational visibility without bypassing controls | Review portfolio-level workload and outcomes | Read all requests and view aggregate analytics; no workflow override |

The roles are deliberately narrow. User administration, organizational structure
maintenance, delegation, and approval overrides are outside the implemented scope.
